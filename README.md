# Telegram-бот АО «Узбекгидроэнерго»

Бот приёма **обращений граждан** и **жалоб на коррупцию** (с анонимной подачей).
Мультиязычный (5 локалей), с ролевой маршрутизацией обращений ответственным
лицам, статусами, ответами заявителю и аудитом.

## Возможности

- 🌐 5 языков: русский, каракалпакский, узбекский (кириллица и латиница), английский. Выбор при `/start`, смена в любой момент.
- 📝 Обращения граждан и 🛡 жалобы на коррупцию через пошаговую форму (ФИО, телефон, текст, фото/документы — включая альбомы).
- 🕵 **Анонимная** подача жалоб: ФИО/телефон не сохраняются; tg_id заявителя хранится только в зашифрованном виде (ключ — вне БД), ответ доставляется push.
- 📋 «Мои обращения» — статусы своих обращений (анонимные не показываются).
- 👥 Ответственные лица получают карточку обращения, могут «взять в работу» (атомарно, кто первый), ответить и закрыть; ответ пересылается заявителю на его языке.
- 🔐 Полный аудит действий (смена статусов, назначения ролей, ответы) без PII.
- 🚦 Антифлуд (throttling), PII-safe логирование.

## Стек

Python 3.11+, aiogram 3.x, aiogram-i18n + Fluent, PostgreSQL (SQLAlchemy 2.0 async + asyncpg) + Alembic, Redis (FSM + throttling), Docker. Запуск — polling (тест) или webhook (прод).

## Быстрый старт (Docker)

1. Скопируйте `.env.dist` → `.env` и заполните:
   - `BOT_TOKEN` — токен от @BotFather;
   - `ADMIN_IDS` — Telegram ID администраторов (через запятую);
   - `ANON_ENC_KEY` — сгенерируйте: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`;
   - `POSTGRES__PASSWORD`, `REDIS__PASSWORD` — пароли;
   - для прода: `USE_WEBHOOK=true`, `WEBHOOK_URL` (HTTPS), `WEBHOOK_SECRET`.
2. `make up` (или `docker compose up -d --build`).

Миграции применяются автоматически отдельным one-shot job `migrate` перед стартом бота.

## Локальный запуск (без Docker)

```bash
make install
# поднимите PostgreSQL и Redis, заполните .env (POSTGRES__HOST=localhost ...)
make migrate
make run
```

## Разработка

- `make lint` — ruff.
- `make test` — pytest. Конкурентные тесты идут против реального Postgres: задайте `TEST_PG_DSN=postgresql+asyncpg://...`, иначе они пропускаются.
- `make migration m="описание"` — новая Alembic-ревизия.

## Назначение ответственных

Администратор (из `ADMIN_IDS`) использует команды бота:

- `/assign` — переслать сообщение пользователя или указать его ID, затем выбрать тип ответственности (обращения / жалобы).
- `/responsibles` — список ответственных и снятие ролей.

## Безопасность и приватность (важно для прод)

- **Анонимность** защищает от утечки через дамп БД (нет открытого автора у анонимной жалобы). Она **не** защищает от оператора, владеющего `ANON_ENC_KEY`: храните ключ в секрет-сторе/KMS, отдельно от БД-бэкапов; ограничьте доступ. Возможна слабая временна́я корреляция (`users.created_at` vs `submissions.created_at`).
- **Вложения**: EXIF/метаданные фото не вырезаются — пользователь предупреждается; для повышенной приватности можно добавить стрипинг.
- **Webhook**: бот слушает `127.0.0.1`; TLS терминируйте на reverse-proxy, наружу публикуйте только прокси. Секрет (`WEBHOOK_SECRET`) высокоэнтропийный, путь непредсказуемый.
- **Бэкапы БД** содержат персональные данные обращений — шифруйте и ограничивайте доступ.
- **Каракалпакские** формулировки — рабочие; перед прод-запуском рекомендуется вычитка носителем (помечено `# TODO: вычитка носителем`).
