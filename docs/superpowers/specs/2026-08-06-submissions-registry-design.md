# Реестр заявок для ответственных и админов — дизайн

**Дата:** 2026-08-06 · **Проект:** anticor-bot · **Статус:** утверждён

## Проблема

Push-карточка — единственный способ добраться до заявки. Если она уехала вверх по чату, пришла в выходной или бот был заблокирован в момент рассылки (`safe_send` молча глотает `TelegramForbiddenError`, [services/submissions.py:250](../../../bot/services/submissions.py#L250)), заявка недостижима навсегда. Ответственный не может ни посмотреть свою очередь, ни найти старое обращение.

## Ключевой принцип

**Реестр — новая точка входа к существующим правам, а не новые права.**

| | Push-карточка (сейчас) | Реестр (новое) |
|---|---|---|
| Кому доступно | всем `resp_<type>` | тем же `resp_<type>` |
| Видно по анонимке | `🕵 Анонимно` + текст | то же самое |
| Действия | взять / ответить / закрыть | те же хендлеры |
| Авторизация | `_authorize()` | **тот же** `_authorize()` |

Ни одна строка не становится видимой тому, кто не увидел бы её в карточке. Инвариант анонимности не затрагивается: реестр читает те же поля, которые сервис уже занулил на записи ([services/submissions.py:91](../../../bot/services/submissions.py#L91)), и **никогда** не обращается к `anon_delivery_refs.enc_chat_ref`.

## Объём

### Входит

1. Пункты главного меню и команды `/` — по роли.
2. Постраничный список (5 на страницу) с фильтром по статусу и сортировкой.
3. Детальный просмотр заявки с действиями (взять / ответить / закрыть).
4. Навигация «К списку» с сохранением фильтра и страницы.

### Не входит (явно отложено)

Поиск по номеру заявки · фильтр «только мои» · админское переназначение исполнителя · экспорт · просмотр вложений из реестра.

## Модель доступа

Тип фиксируется **на входе** и внутри реестра не меняется:

```
resp_appeal=True     → «📝 Обращения»  + /appeals
resp_corruption=True → «🛡 Жалобы»     + /complaints
is_admin=True        → оба пункта и обе команды
гражданин            → меню как сейчас, команд нет
```

Следствие: фильтр по типу внутри реестра **не нужен** — тип уже задан и лишь проверяется против роли пользователя.

Проверка доступа переиспользует `can_handle_type(user, type_)` ([filters/roles.py:37](../../../bot/filters/roles.py#L37)) — ту же функцию, что гейтит действия с карточки. Отдельной логики доступа у реестра нет.

## Состояние в callback_data, без FSM

```python
class RegistryCb(CallbackData, prefix="reg"):
    type: str      # appeal | corruption
    status: str    # all | new | in_progress | closed
    order: str     # desc | asc
    page: int
    open: str      # "" = список, иначе public_id заявки
```

Худший случай упаковки — 48 байт при лимите Telegram в 64 (проверено). Что это даёт:

- **Никакого FSM** — не конфликтует с `SubmissionForm`/`ResponseForm`, не занимает Redis, не истекает по 6-часовому TTL.
- **«К списку» бесплатна** — фильтр и страница уже в payload, возврат восстанавливает ровно тот же экран.
- **Переживает рестарт бота** — старая клавиатура остаётся рабочей.

## Взаимодействие

Одно сообщение, `edit_message_text` на каждое действие — чат не засоряется.

```
СПИСОК                          ДЕТАЛИ
🗂 Жалобы · 🆕 Новые             🛡 Жалоба на коррупцию
                                🕵 Анонимно
1. 🆕 K7M2QP4A · 🕵 · 02.08      Текст: ...
2. 🆕 B3XR9T2C · Иванов · 01.08  Статус: 🆕 Новое
3. 🆕 F8N4WK1D · 🕵 · 31.07
4. 🆕 P2QL7Z9M · Петров · 30.07  [🟡 Взять в работу]
5. 🆕 R5TY3X8B · 🕵 · 29.07      [✍ Ответить]
                                [🔒 Закрыть]
[1][2][3][4][5]        ←клик→   [◀ К списку]
[Все][🆕][⏳][✅]
[↓ Новые][↑ Старые]
[◀ 1/4 ▶]
```

Строка списка: `<статус> <public_id> · <автор|🕵> · <дата>`. У анонимных вместо ФИО — `🕵`; текст виден только в деталях (как в карточке). Если у неанонимной заявки `full_name` пустое — показываем `—` (не подставляем `username`/`tg_id`: в списке это лишний идентификатор). ФИО проходит через `escape()` — строка уходит в HTML parse mode.

### Запрос — единственное место с новым SQL

```python
async def list_for_registry(
    self, *, type_: SubmissionType, status: SubmissionStatus | None = None,
    order: str = "desc", page: int = 0, per_page: int = 5,
) -> tuple[list[Submission], int]:
    """Страница реестра + общее число строк (для «1/4»)."""
```

Индексы под это уже есть: `submissions.status` и `submissions.type` проиндексированы ([db/models.py:77](../../../bot/db/models.py#L77)).

### Действия не дублируются

Кнопки в деталях — это существующие `ReactionCb`, которые уже обрабатывает `responsible.py` с его `_authorize()`. Дублирующего хендлера в registry **нет** — иначе авторизация расщепится на две копии, которые разъедутся.

Вместо этого `responsible.py` в конце успешного действия вызывает `registry.refresh_detail(query, ...)`. Хелпер — no-op, если клик пришёл с push-карточки, и перерисовывает экран, если из реестра (различается по наличию `RegistryCb` в клавиатуре исходного сообщения). Авторизация остаётся в одном месте.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Заявка удалена между списком и кликом | алерт + возврат к списку |
| Пустая страница после смены фильтра | «нет заявок», `page` сбрасывается на 0 |
| Тап по уже активному фильтру | Telegram даёт `TelegramBadRequest: message is not modified` → ловим, тихий `query.answer()` |
| Гражданин набрал `/appeals` руками | гейт фильтра, ответ `admin-only` |
| Клавиатура пережила смену роли | `can_handle_type` перепроверяется на каждый клик → алерт |

## Персональное меню команд

`BotCommandScopeChat` обновляется в двух точках: `on_assign_type` и `on_revoke` ([handlers/admin.py:50](../../../bot/handlers/admin.py#L50), [:110](../../../bot/handlers/admin.py#L110)).

⚠️ **Критично:** `set_my_commands` с чат-скоупом **заменяет** весь список для этого чата, а не дополняет глобальный. Персональный список обязан включать базовые команды (`/start`, `/language`, `/cancel`) + реестровые — иначе назначение роли ломает пользователю `/start` в меню. При снятии последней роли чат-скоуп удаляется (`delete_my_commands`), чтобы вернулся глобальный список.

Персональное меню — **UX, а не авторизация**: команду можно набрать руками, поэтому хендлеры гейтятся фильтрами независимо.

2. **`test_registry_query.py`** — `list_for_registry`: фильтр по статусу, порядок `desc`/`asc`, границы пагинации, корректный `total`.
3. **`test_registry_flow.py`** — через `Dispatcher.feed_update`: список → фильтр → страница → открыть → «К списку» восстанавливает фильтр и страницу.
